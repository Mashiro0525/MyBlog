## 12. 给射线检测添加分支检查后，运行关卡时点击静态网格体时屏幕无反应，设计的属性查询UI界面未显示，如何排查点击无反应的原因

**问题：** 给射线检测添加分支检查后，运行关卡时点击静态网格体时屏幕无反应，设计的属性查询UI界面未显示，如何排查点击无反应的原因

**答案：** 当射线检测添加了防御性分支逻辑后，UI 不显示通常意味着射线根本没有检测到该物体，或者检测到了但数据匹配失败。

请按照以下步骤按顺序排查，这是解决此类问题的标准流程：

1. 开启可视化调试（排查物理碰撞）

首先要确认射线是否真的“碰”到了你的静态网格体。

操作：在 Line Trace By Channel 节点上，将 Draw Debug Type 设置为 For Duration（持续）或 One Frame（单帧）。

观察：运行关卡并点击。

红色/绿色线条：如果线条直接穿过了网格体而没有产生红点（命中点），说明该网格体的碰撞设置有问题。

没有线条：说明你的射线检测起点或终点坐标计算错误，射线没射出来。

2. 检查静态网格体的碰撞属性

静态网格体默认可能没有开启碰撞，或者通道不匹配。

操作：选中关卡中的静态网格体，在 Details (细节) 面板搜索 Collision。

检查项：

Collision Presets：确保不是 NoCollision。建议设为 BlockAll 或 Custom。

Trace Responses：如果你射线用的是 Visibility 通道，请确保该网格体对 Visibility 的响应是 Block（阻塞）。如果设为 Ignore 或 Overlap，射线会直接穿透。

3. 验证 Actor Tags 匹配性

如果射线有命中点（红点），但 UI 没出，说明 Get Data Table Row 没查到数据。

操作：在 Get Tags 节点后面接一个 Print String。

检查项：

输出的 Tag 字符串是否与数据表里的 Row Name 完全一致（注意：空格、大小写、中英文符号必须一模一样）。

如果输出为空，说明你没在关卡物体的 Tags 数组里填入 ID。

4. UI 显示逻辑检查

如果数据查到了，但屏幕还是黑的，可能是 UI 的问题。

操作：在 Get Data Table Row 的 Row Found 后面接一个 Print String。

结论：

如果打印了信息但没见 UI：检查 Add to Viewport 是否已执行，或者 UI 的 Z-Order 是否被其他 UI 挡住了。

Visibility 设置：确保你没有误将 UI 的 Visibility 设为 Hidden 或 Collapsed 后忘记在逻辑中改回 Visible。

5. 输入模式干扰

操作：检查你是否在点击时触发了其他会拦截鼠标的 UI。

如果你的鼠标被用于控制视角（FPS 模式），确保点击事件通过 Input Action 正确触发了射线检测逻辑。

## 13. 射线检测将Draw Debug Type 设置为 For Duration后，运行关卡后点击没有出现线条

**问题：** 射线检测将Draw Debug Type 设置为 For Duration后，运行关卡后点击没有出现线条

**答案：** 如果将 Draw Debug Type 设置为 For Duration 后仍然没有看到任何线条，这说明射线检测的起点（Start）和终点（End）坐标计算错误，或者该逻辑根本没有被触发。

请按以下步骤依次检查并 eliminate（排除）问题：

1. 检查逻辑触发点（Print String 检查）

首先确认你的点击事件是否生效。

操作：在鼠标点击事件（例如 Left Mouse Button 或 Input Action）之后，连接一个 Print String 节点。

排查：如果运行点击时左上角没有弹出 “Hello”，说明你的输入设置有问题，或者该 Pawn/Character 没有开启 Auto Receive Input。

2. 检查射线端点坐标 (Start & End)

线条不出现，最常见的原因是 Start 和 End 坐标完全重合，或者数值变成了 0。

排查起点：如果你从摄像机开始，请确保连线是 Camera -> Get World Location。

排查终点：射线需要一个方向和长度。常见的错误公式是只连了方向，忘记了加起点。

正确公式：Start + (Forward Vector * 距离)。

如果只把 Forward Vector 连到 End，射线长度可能只有 1 厘米（在坐标 0,0,0 附近），你根本看不见。

3. 验证坐标数值（Debug 数值）

在 Line Trace 节点前，将 Start 和 End 的向量值打印出来：

操作：使用 Print String 打印 Start 和 End 的坐标。

预期：如果看到的数值是 X=0, Y=0, Z=0，说明你获取位置的组件引用（如 Camera）为空，或者引脚连错了。

4. 解决“鼠标模式”下的射线问题

如果你是做鼠标点击（类似策略游戏或点击解谜），直接使用射线检测坐标比较复杂。

推荐替代方案：使用 Get Hit Result Under Cursor by Channel。

节点：Get Player Controller -> Get Hit Result Under Cursor by Channel。

这个节点会自动根据鼠标点击的屏幕位置发射射线，不需要你手动计算 Start 和 End。

注意：记得在 Player Controller 中勾选 Enable Click Events。

5. 常见原因清单

输入模式拦截：如果你当前处于 UI Only 输入模式，鼠标点击会被 UI 拦截，射线逻辑不会触发。

距离太短：检查你的 Vector * Float 节点，Float 数值（距离）至少应该是 500 到 2000。如果是 0，则看不见线条。

世界原点偏差：如果物体距离世界中心（0,0,0）非常远，而你的坐标计算有误，射线可能射向了完全相反的方向。

6. 逻辑消除 (Elimination) 步骤总结

断点检查：在 Line Trace 节点上按 F9 设置断点，点击时看程序是否停下。

视觉确认：将 Draw Debug Type 设为 Persistent（永久），看是否在世界原点留下了极小的线段。

引用检查：确保用于计算位置的 Camera 组件已被 eliminate（排除）掉空引用的可能（即确保它在层级中存在且已激活）。

建议方案：如果手动计算 Start/End 失败，请改用 Get Hit Result Under Cursor by Channel，这是处理“点击查询”最稳健、最不容易出错的方法。

## 14. 改为使用Get Hit Result Under Cursor by Channel后，如何判断射线检测是否命中网格体

**问题：** 改为使用Get Hit Result Under Cursor by Channel后，如何判断射线检测是否命中网格体

**答案：** 在使用 Get Hit Result Under Cursor by Channel 节点后，判断是否命中网格体需要结合 布尔返回值 和 命中结果拆解。

以下是标准的操作步骤和逻辑判断流程：

1. 基础命中判断 (布尔检查)

该节点左侧有一个红色的布尔输出引脚 Return Value。

含义：它表示鼠标下的射线是否碰撞到了任何符合通道要求（如 Visibility）的物理表面。

操作：首先连接一个 Branch (分支) 节点。如果为 False，说明点击了天空或无碰撞区域，应直接 eliminate（排除）后续逻辑，并隐藏 UI。

2. 详细结果拆解 (Break Hit Result)

在 Branch 的 True 路径下，你需要分析命中的具体对象：

右键点击 Hit Result 引脚，选择 Split Struct Pin (分割结构体引脚)，或者连接一个 Break Hit Result 节点。

找到 Hit Actor 引脚。

3. 验证是否为目标网格体

即使命中了物体，那也可能是地板或墙壁。你需要通过以下两种方式之一来确认：

方案 A：通过 Actor Tag 验证 (推荐)

如果你在之前的步骤中给特定物体设置了标签（如 Item）：

从 Hit Actor 拉出引脚，调用 Actor Has Tag。

输入你的标签名称。

再接一个 Branch。只有为 True 时才执行数据表查询。

方案 B：通过类型验证 (Casting)

如果你想确认命中的是否是特定的蓝图类：

从 Hit Actor 拉出引脚，调用 Cast to StaticMeshActor 或你的自定义蓝图类（如 BP_Collectable）。

转换成功说明命中目标。

5. 关键注意事项

启用点击事件：在你的 PlayerController 细节面板中，必须勾选 Enable Click Events 和 Enable Mouse Over Events，否则该节点可能无法获取实时点击反馈。

碰撞通道：默认通常选择 Visibility。请确保你的静态网格体的碰撞预设（Collision Presets）中，Visibility 通道被设置为 Block。

消除 Accessed None 错误：在访问 Hit Actor 之前，务必使用 Is Valid 节点。如果射线命中的是瞬间被 eliminate（消除）掉的物体，或者是不稳定的物理对象，直接读取属性会导致崩溃或报错。

6. 调试小技巧

如果在 Branch 处总是返回 False：

在 Get Hit Result Under Cursor by Channel 节点上，将 Trace Channel 尝试切换为 Camera。

检查静态网格体是否勾选了 Generate Overlap Events（虽然射线检测主要看 Block，但某些复杂设置下会有影响）。

通过这个层层递进的判断逻辑，你可以确保只有在玩家真正点击到有效目标时，才会触发属性显示的 UI。

## 15. 射线检测点击命中的对象是仅存在于关卡中的静态网格体，使用Hit Actor引脚是否依然有效

**问题：** 射线检测点击命中的对象是仅存在于关卡中的静态网格体，使用Hit Actor引脚是否依然有效

**答案：** 是的，Hit Actor 引脚依然完全有效。

即使你只是简单地将一个静态网格体（Static Mesh）从内容浏览器直接拖入关卡，它在场景中也会自动被封装在一个名为 StaticMeshActor 的容器中。在 Unreal Engine 的架构中，关卡里的任何独立对象都必须是一个 Actor 才能存在。

以下是关于这种情况的详细技术说明和操作建议：

1. 为什么它有效

当你点击关卡里的静态网格体时：

Hit Actor：返回的是该物体在场景中的实例（即 StaticMeshActor）。

Hit Component：返回的是该 Actor 内部存储模型数据的 StaticMeshComponent。

你可以直接通过 Hit Actor 引脚来获取标签（Tags）或进行类型转换。

2. 具体的判定与操作逻辑

方案 A：使用 Actor 标签 (推荐)

如果你想通过标签来识别它，请确保你在正确的地方填写了标签：

在关卡编辑器中选中该静态网格体。

在 Details (细节) 面板中，搜索 Tags。

注意：会有两个 Tags 栏。请使用 Actor > Tags（底部的那个），而不是 Component Tags。

在蓝图中，从 Hit Actor 引脚拉出 Actor Has Tag 即可成功识别。

方案 B：类型检查

如果你想在代码中过滤，确保点到的是静态网格体而不是其他（如光源、大气）：

从 Hit Actor 拉出引脚，调用 Cast to StaticMeshActor。

如果转换成功，说明你命中的确实是一个直接拖入关卡的标准静态网格。

3. 逻辑图谱 (Graph Recipe)

4. 潜在的陷阱与消除 (Elimination)

消除“无反应”：如果你发现 Hit Actor 返回了物体，但 Actor Has Tag 始终为 False，通常是因为标签填到了组件（Component Tags）里。请务必检查并 eliminate 这个配置错误。

碰撞层级：静态网格体必须有 碰撞（Collision） 才能被检测。如果该网格体没有简单的碰撞盒（Simple Collision），射线会直接穿透。

排查方法：双击打开该静态网格体资产，在菜单栏查看 Collision，确认是否有青色的碰撞线。

层级清理：如果该物体在游戏中被 eliminate（例如通过 Destroy Actor 消除），Hit Actor 将返回无效引用。使用 Is Valid 节点可以完美避免此类报错。

总结：直接拖入关卡的网格体完全支持 Hit Actor 引脚。你只需确保在 Actor 层面设置好标签，并使用 Is Valid 节点进行防御性检查即可。

## 16. 如何给静态网格体设置碰撞属性

**问题：** 如何给静态网格体设置碰撞属性

**答案：** 给静态网格体（Static Mesh）设置碰撞属性主要分为两个阶段：在静态网格体编辑器中生成几何碰撞，以及在细节面板中配置物理响应。

以下是详细的操作步骤：

1. 生成几何碰撞 (Collision Geometry)

如果物体没有青色的碰撞外壳，射线会直接穿透。

在 Content Browser (内容浏览器) 中双击打开你的静态网格体资产。

在顶部菜单栏点击 Collision (碰撞) 按钮。

选择以下常用选项之一：

Add Box Simplified Collision：适用于箱子、柜子。

Add Capsule/Sphere Simplified Collision：适用于圆柱体或球体。

Add 10DOP Simplified Collision：生成更紧贴物体的凸包。

Auto Convex Collision（在右下角面板）：适用于复杂形状，点击 Apply 生成。

验证：点击工具栏的 Show (显示) > Collision，如果你能看到青色的线条包裹住模型，说明几何碰撞已生效。

2. 设置碰撞复杂度 (Complexity)

如果你的模型非常精细（如空心的圆环），简单的碰撞盒无法满足需求：

在静态网格体编辑器右侧的 Details (细节) 面板中，搜索 Collision Complexity。

将其设置为 Use Complex Collision As Simple。

这会将模型的三角面直接作为碰撞体，射线检测将极其精确，但会略微增加物理计算开销。

3. 配置关卡中的物理响应 (Collision Presets)

生成了几何体后，你还需要告诉引擎它是否应该阻塞“射线”。

在关卡编辑器中选中该物体。

在 Details (细节) 面板中找到 Collision 分类。

Collision Presets：建议设置为 BlockAll 或 Default。

手动配置 (如果使用 Custom)：

确保 Collision Enabled 设为 Query and Physics。

在下方的 Trace Responses 中，找到 Visibility（或你射线使用的通道），将其勾选为 Block (阻塞)。

4. 关键排查与消除 (Elimination)

消除穿透问题：如果射线仍然穿透，检查 Collision Presets 是否被误设为了 NoCollision 或 Trigger（Trigger 默认不阻塞 Visibility 通道）。

消除冗余碰撞：如果在编辑器里看到重叠的青色线条，可以在 Collision 菜单下选择 Remove Collision，然后重新生成一个最简单的。

运行时验证：在游戏中按下 ~ 键打开控制台，输入 show collision。如果你在视口中看不到物体的碰撞外壳，说明该物体的碰撞已被 eliminate（移除）或未正确加载。

5. 性能建议

优先使用简单碰撞：尽量使用 Box 或 Capsule。只有在必须进行精确点击（如点击狭缝中的按钮）时，才开启 Complex Collision。

优化射线通道：对于仅用于属性查询的物体，可以自定义一个 Trace Channel，专门用于此功能，以 eliminate 与其他物理逻辑（如子弹、角色移动）的潜在冲突。

## 17. 在玩家角色蓝图中，已给鼠标左键绑定了点击按压可旋转事件，现在我想让属性查询窗口在点击静态网格体时才显示，应该如何修改

**问题：** 在玩家角色蓝图中，已给鼠标左键绑定了点击按压可旋转事件，现在我想让属性查询窗口在点击静态网格体时才显示，应该如何修改

**答案：** 在同一个“鼠标左键”事件中同时处理旋转视角和属性查询，关键在于区分玩家是想“点击”还是“拖拽”。如果点击时命中了物体，则显示 UI；如果玩家是在按住并移动鼠标，则执行旋转。

以下是修改方案：

1. 核心逻辑设计

Pressed (按下)：记录当前鼠标位置，并开启旋转逻辑。

Released (松开)：计算按下到松开的时间或位移。如果是短促的点击且命中了目标，则显示属性 UI。

Pressed：设置变量为 True。

Released：设置变量为 False。

在你的 Mouse Input 轴事件中，添加一个 Branch，只有当变量为 True 时才执行旋转。

第二步：添加射线检测逻辑（在 Released 分支）

为了确保玩家不是在旋转镜头时触发 UI，我们在 Released 节点进行判断：

从 Released 拉出引脚。

调用 Get Hit Result Under Cursor by Channel。

按照之前的逻辑：Branch (Return Value) -> Is Valid -> Actor Has Tag。

只有在满足条件时：调用 HUD 里的 ItemInfoWidget 显示出来。

第三步：处理输入模式切换

为了让属性窗口出现后可以点击上面的“关闭”按钮：

在显示 UI 的逻辑末尾，调用 Set Input Mode Game And UI。

勾选 Set Show Mouse Cursor。

5. 性能与最佳实践

避免 Tick：旋转逻辑放在 Axis 事件中，射线检测放在 Released 事件中。这样可以 eliminate 不必要的每帧计算。

输入优先级：如果主菜单已打开，应优先处理菜单逻辑。可以在执行射线检测前增加一个检查，如果 MainMenu 可见，则直接结束。

通过将 UI 触发放在 Released 阶段并配合简单的位移/状态检查，你可以完美兼容旋转视角与物体查询功能。

## 19. 如果我只给鼠标左键新绑定一个点击后进行射线检测的事件，但不改变原来的鼠标左键拖拽进行视角旋转的逻辑，这样会影响视角旋转的…

**问题：** 如果我只给鼠标左键新绑定一个点击后进行射线检测的事件，但不改变原来的鼠标左键拖拽进行视角旋转的逻辑，这样会影响视角旋转的运行吗

**答案：** 简单来说：会有影响，且会产生严重的逻辑冲突。

在 Unreal Engine 中，如果你为同一个按键（鼠标左键）绑定了两个独立的逻辑（一个是原有的旋转，一个是新增的射线检测），系统会同时执行它们，除非你进行了明确的隔离。

1. 冲突的具体表现

功能重叠：当你点击静态网格体想查询属性时，视角也会跟着晃动。

误触发：当你只想旋转视角看风景时，松开鼠标的一瞬间，如果准星刚好对准了一个带标签的物体，属性窗口会突然弹出，打断你的游戏体验。

输入拦截 (Consume Input)：在蓝图事件设置中，有一个选项叫 Consume Input（消耗输入）。如果新增的事件勾选了此项，它可能会彻底 eliminate（消除）掉原有旋转逻辑的响应，导致视角旋转完全失效。

2. 为什么不建议“各走各的”

即使你不在同一个节点序列里写逻辑，只要它们监听的是同一个物理按键，引擎就会并行触发。这会导致玩家意图（Intent）的混乱——引擎无法自动判断你这一下点击是为了“看东西”还是为了“转头”。

3. 最佳解决方案：意图过滤 (Intent Filtering)

为了确保旋转逻辑不被破坏，同时又能进行查询，你必须在 Released（松开） 事件中加入一个“位移阈值”检查，来 eliminate 旋转产生的误操作。

推荐的修改逻辑：

保留旋转逻辑：让它继续在 Pressed 时开启 Gate 旋转。

在 Released 节点后增加分支：

计算鼠标按下到松开的位移。

如果是大位移：判定为旋转结束，什么都不做。

如果是极小位移（点击）：这时才执行射线检测（Get Hit Result Under Cursor）。

4. 操作建议 (Step-by-Step)

找到你现有的鼠标左键 Pressed/Released 节点。

在 Pressed 后面增加：Get Mouse Position -> 存为变量 Vector2D_Start。

在 Released 后面（即关闭 Gate 之后）：

Get Mouse Position -> 与 Vector2D_Start 相减并取长度（Distance）。

添加 Branch：如果长度 < 5（像素）。

True 路径：执行 Get Hit Result Under Cursor（属性查询）。

False 路径：什么都不做（判定为旋转结束）。

5. 关于“消耗输入”的性能提示

如果你在不同的地方多次使用 Left Mouse Button 事件：

选中该事件节点，在 Details 面板查看 Consume Input。

如果你希望两个地方都跑，必须取消勾选它。

但最专业、最易于调试的方法是将所有左键逻辑集中在一个地方，通过分支导航。这样可以彻底 eliminate 掉逻辑执行顺序不确定带来的 Bug。

结论：不加修改地直接绑定新事件会造成视角乱跳和 UI 误弹出。通过添加一个简单的位移检查，你可以保护原有的旋转运行，同时让查询逻辑仅在真正的“点击”动作中生效。

## 20. 鼠标左键的Released事件后连接了gate的close引脚，如何在关闭gate之后添加获取鼠标位置的事件

**问题：** 鼠标左键的Released事件后连接了gate的close引脚，如何在关闭gate之后添加获取鼠标位置的事件

**答案：** 在蓝图中，Gate 节点的 Close 输入引脚没有输出执行流。如果你想在关闭 Gate 的同时（或之后）执行其他逻辑（如获取鼠标位置进行射线检测），你需要改变连线方式。

以下是两种最专业的方法来处理这个逻辑：

方法 A：使用 Sequence（序列）节点（推荐）

这是最清晰的做法，可以确保“关闭 Gate”和“后续逻辑”同时被触发，且互不干扰。

在 Released 事件节点后，连接一个 Sequence 节点。

将 Then 0 引脚连接到 Gate 的 Close 输入端。

将 Then 1 引脚连接到 Get Mouse Position 或 Get Hit Result Under Cursor。

逻辑图谱：

[Left Mouse Button: Released]
 |
[Sequence]
 |--- (Then 0) ---> [Gate: Close] (停止旋转)
 |
 |--- (Then 1) ---> [Get Mouse Position] (开始查询逻辑)

方法 B：直接串联执行流

虽然 Close 引脚本身没有输出，但你可以先执行查询逻辑，最后再连向 Close；或者先执行关闭动作，在同一条线上继续往后连。

从 Released 连出，先连接 Get Mouse Position（及其后续位移判断和射线检测）。

在整条逻辑链的最末端，或者在起始位置，分出一根线连给 Gate 的 Close。

注意：即便执行流先经过了获取位置的逻辑，只要它最终能触发 Close，Gate 就会正常关闭。

3. 为什么 Close 引脚没有输出？

在 Unreal Engine 的蓝图设计中，Open、Close、Toggle 都是动作输入（Impulse Only）。它们只负责改变 Gate 内部的状态（开或关），不会让执行信号穿过它们继续向右传递。只有进入 Enter 引脚的信号才会从 Exit 流出。

4. 完整的整合方案 (实现点击+旋转)

为了 eliminate（消除）旋转带来的干扰，建议按照以下顺序组装：

Released 触发。

Sequence (Then 0)：立即连接 Gate 的 Close。这会瞬间停止视角的旋转计算。

Sequence (Then 1)：获取 EndPos（当前鼠标位置）。

计算 StartPos (Pressed时记录的) 与 EndPos 的距离。

Branch：如果距离很小（例如 < 10）：

执行 Get Hit Result Under Cursor by Channel。

执行 Break Hit Result -> Actor Has Tag。

显示 UI。

5. 调试技巧与消除 (Elimination)

消除顺序 Bug：如果你先执行复杂的射线检测逻辑，可能会导致 Gate 的关闭延迟几毫秒。虽然在高性能 PC 上不明显，但在掉帧时可能会导致视角多晃动一下。因此，使用 Sequence 并优先执行 Close 是最稳健的。

打印位置：在 Sequence (Then 1) 后面接一个 Print String 打印鼠标位置。如果你点击时能看到坐标输出，说明执行流已成功绕过 Gate 的输入限制。

通过使用 Sequence 节点，你可以完美地在鼠标松开时同时完成“停止旋转运动”和“发起属性查询”这两个独立动作。

## 21. 利用sequence控制流程，整个鼠标左键控制视角旋转与射线检测的逻辑连线是怎样的

**问题：** 利用sequence控制流程，整个鼠标左键控制视角旋转与射线检测的逻辑连线是怎样的

**答案：** 为了确保视角旋转（持续动作）与射线检测（瞬间点击）互不干扰，以下是基于 Sequence 和 Gate 的完整蓝图逻辑连线方案。

1. 核心连线逻辑图解

A. 鼠标按下 (Pressed) - 初始化

Pressed -> Set Vector2D变量 (StartMousePos)：调用 Get Mouse Position 并保存，用于后续位移计算。

Pressed -> Gate: Open：允许视角旋转逻辑开始执行。

B. 鼠标松开 (Released) - 逻辑分流

这是你问题的核心。使用 Sequence 节点来同时处理“停止旋转”和“触发检测”。

Released -> Sequence:

Then 0 -> Gate: Close：立即停止视角旋转（消除惯性）。

Then 1 -> 位移与检测逻辑:

调用 Get Mouse Position 得到 EndMousePos。

使用 Vector2D Distance 节点计算 StartMousePos 与 EndMousePos 的距离。

Branch (分支)：判断距离是否 < 10（像素）。

True (判定为点击) -> 调用 Get Hit Result Under Cursor by Channel。

False (判定为旋转后的松开) -> 不执行任何操作（从而 eliminate 误触）。

C. 视角旋转 (Axis Events) - 持续执行

InputAxis Mouse X / Y -> Gate: Enter。

Gate: Exit -> Add Controller Yaw/Pitch Input。

2. 具体节点 recipe (步骤指南)

[逻辑块 1：按下与旋转控制]

右键添加 Left Mouse Button 事件。

从 Pressed 引脚拉出：

连接到 Gate 节点的 Open 引脚。

连接到一个 Set (Vector2D) 节点，重命名为 StartPos。其值来源于 Get Player Controller -> Get Mouse Position。

[逻辑块 2：松开与射线检测]

从 Left Mouse Button 的 Released 引脚拉出，连接到 Sequence。

Sequence (Then 0)：连接到 Gate 的 Close 引脚。

Sequence (Then 1)：

调用 Get Mouse Position，与变量 StartPos 连接到 Vector2D Distance。

连接 Less Than ( < ) 节点，值设为 10。

连接 Branch：

True：连接 Get Hit Result Under Cursor by Channel。

Break Hit Result -> Hit Actor -> Actor Has Tag (Tag 填 “Item”)。

Branch -> True：执行 Get Data Table Row 并显示 UI。

[逻辑块 3：视角旋转执行]

添加 InputAxis Mouse X (或你的 Enhanced Input 节点)。

连接到上述 Gate 节点的 Enter 引脚。

从 Gate 的 Exit 引脚拉出，连接到 Add Controller Yaw Input。

(Mouse Y 同理)。

3. 排查与消除 (Elimination) 检查清单

消除冲突：如果你发现点击物体时视角依然会轻微晃动，这是因为 Mouse Axis 在 Released 信号发出前的一瞬间仍在工作。这通常没问题，但如果你追求完美，可以在 Sequence (Then 1) 之后添加一极短的 Delay (0.0) 节点再执行射线检测。

消除无效点击：如果点击网格体没反应，请检查 Get Hit Result Under Cursor 的 Trace Channel 是否设为 Visibility，且该网格体的碰撞预设（Collision Presets）确实 Block 该通道。

UI 模式转换：一旦 Row Found 执行并显示 UI，记得调用 Set Input Mode Game and UI 并勾选 Show Mouse Cursor，否则你将无法点击 UI 上的关闭按钮。

4. 最佳实践提示

Input Action (推荐)：如果你使用的是 UE5 的 Enhanced Input，逻辑是相同的：Started 对应 Pressed，Completed 对应 Released。

变量清理：在显示 UI 的逻辑最后，建议将 StartPos 清零，以 eliminate 下一次点击时可能存在的残留数据干扰。

通过这种 Sequence 分流方案，你可以确保“旋转”和“查询”这两套逻辑在玩家操作意图上被清晰地划分开。

## 95. 使用射线检测（Line Trace）获取精准地面的详细蓝图连线逻辑

**问题：** 使用射线检测（Line Trace）获取精准地面的详细蓝图连线逻辑

**答案：** 为了获取精准的着陆位置并消除 (Elimination) 角色飞向远方或卡进地面的问题，你需要利用射线检测来计算角色正下方的物理碰撞点。

以下是详细的蓝图连线步骤与逻辑配方：

1. 核心逻辑概述

该逻辑会从角色当前的位置向下发射一条不可见的射线，找到第一个碰撞到的物体表面，并将角色的位置精确设置为该点（加上角色自身高度的偏移）。

2. 详细蓝图连线逻辑 (Graph Recipe)

第一步：获取起始点与终点

Get Actor Location: 获取角色当前所在的位置（作为射线的起点）。

Break Vector: 将位置拆分为 X, Y, Z。

Subtract (Float): 将 Z 减去 2000（这决定了射线的探测深度）。

Make Vector: 将原有的 X, Y 和减去后的 Z 重新组合（作为射线的终点）。

第二步：执行射线检测

Line Trace By Channel:

Start: 连接第一步的初始位置。

End: 连接第一步计算出的终点位置。

Trace Channel: 保持为 Visibility。

Draw Debug Type: 建议在测试时设为 For Duration 以便肉眼观察。

第三步：处理碰撞结果

Branch: 连接 Line Trace 的 Return Value。只有命中地面时才执行后续逻辑，消除 (Elimination) 掉空转浪费。

Break Hit Result: 从 Out Hit 引脚拉出该节点。

获取 Capsule Half Height: 获取 Character 自身的 CapsuleComponent，从中拉出 Get Scaled Capsule Half Height。

原因：Hit Location 是地面的坐标，如果你直接把角色中心点移过去，角色会有一半卡在地下。我们需要加上半高来消除 (Elimination) 这种偏移。

第四步：执行传送 (Teleport)

Vector + Vector:

A: Break Hit Result 里的 Location（或者 Impact Point）。

B: 将其 Z 轴增加刚才获取的 Capsule Half Height（可以再额外 +2.0 确保悬空一点点）。

Teleport:

Dest Location: 连接相加后的结果。

Dest Rotation: 连接 Get Control Rotation。

3. 完整逻辑顺序总结

[切换按钮点击] 
 |
(Exec) -> [Stop Movement Immediately]
 |
(Exec) -> [Line Trace By Channel] (Start: Current Loc, End: Current Loc.Z - 2000)
 |
 [True] -> [Break Hit Result]
 |
(Exec) ----> [Teleport] (Location: Hit Location + Capsule Half Height)
 |
(Exec) ----> [Set Movement Mode (Walking)]
 |
(Exec) ----> [Set Gravity Scale (1.0)]
4. 关键参数排查

消除 (Elimination) 穿透错误：确保你的地面 Actor 的 Collision Presets 包含对 Visibility 通道的阻挡（Block）。

Trace Complex: 在 Line Trace 节点上勾选 Trace Complex 可以提高碰撞检测的精度，特别是在复杂的建筑模型上。

Actor to Ignore: 在 Line Trace 的 Actors to Ignore 引脚上连接一个 Make Array，并把 Self（角色自己）放进去，防止射线打在角色自己的模型上导致计算错误。

5. 效果验证

执行后，你应该能看到一条红线从角色脚下垂直向下击中地面。角色会瞬间被放置在红线击中点的上方，并由于 Walking 模式和重力的开启，稳稳地落在地上。这种方法彻底消除 (Elimination) 了对地面 Actor 中心点坐标的依赖。

## 196. 我设置了点击鼠标中键作为起始事件，连接到分支节点，将“按通道获取光标下的命中结果”节点中的“Return Value”作…

**问题：** 我设置了点击鼠标中键作为起始事件，连接到分支节点，将“按通道获取光标下的命中结果”节点中的“Return Value”作为分支判断条件，返回的Hit Result Impact Point值连接到打印字符串的In String上，运行后点击鼠标中键，屏幕上未打印字符，如何解决

**答案：** 如果点击中键后没有任何字符打印，说明逻辑在“输入触发”、“射线检测”或“分支判断”这三个关键节点中的某一个被阻断了。

请按照以下步骤进行排查，以消除 (Elimination) 逻辑中断的问题：

1. 验证事件是否触发 (输入检测)

首先确认鼠标中键点击是否真的被引擎捕获。

操作：在“鼠标中键”事件节点与“分支（Branch）”节点之间，插入一个 Print String，内容填“Event Fired”。

排查结果：

如果不打印：说明输入未激活。请检查：

Input Action：如果你使用的是增强输入（Enhanced Input），确保已经在 Input Mapping Context 中绑定了中键。

消费输入 (Consume Input)：在节点细节面板中，检查是否勾选了 Consume Input，有时其他地方占用了中键。

获取焦点：点击运行后，先在视口中左键点击一下，确保窗口获得了输入焦点。

2. 检查 Player Controller 配置 (光标可见性)

“按通道获取光标下的命中结果”依赖于鼠标在屏幕上的坐标。

操作：在 BeginPlay 中调用 Set Show Mouse Cursor 并设为 True。

原因：如果鼠标光标完全不可见或被锁定，光标位置可能停留在屏幕边缘，导致射线投射到了虚无空间，从而消除 (Elimination) 了命中的可能性。

3. 分支节点的 False 处理 (逻辑漏洞)

你提到将 Return Value 连到了分支。

排查逻辑：如果射线没有打中任何带有碰撞的物体（比如只打到了背景天空），Return Value 为 False。

操作：从 Branch 的 False 节点拉出另一个 Print String，填入“Missed”。

结论：如果运行后打印了“Missed”，说明输入有效，但碰撞检测失败了。

4. 碰撞通道设置 (最核心原因)

节点默认使用的通道是 Visibility。

检查目标物体：选中你关卡中想要点击的那个建筑或物体。

细节面板：找到 Collision > Collision Presets。

关键点：确保该物体的 Visibility 响应被设为了 Block（阻挡）。

消除干扰：如果设为 Ignore 或 Overlap，射线会直接穿透物体，导致 Return Value 永远为 False。

5. 坐标转换与打印

Impact Point 是一个 Vector（向量），如果你直接连到 In String，引擎会调用自动转换逻辑。

检查：确保 Print String 的 Duration（时长）不是 0。如果是 0，字符会瞬间消失。

手动转换：尝试手动使用 Vector to String 节点，并检查坐标是否正确（例如是否全是 0）。

总结排查建议 (Graph Recipe)

请按以下顺序重新连接节点进行测试：

Middle Mouse Button Event -> Print String (“Event Start”)

Print String -> Get Hit Result Under Cursor by Channel (Trace Channel: Visibility)

Return Value -> Branch

Branch (True) -> Print String (连接 Hit Result Impact Point)

Branch (False) -> Print String (“No Hit Detected”)

通过这种两头堵截的方法，你可以精准定位是点击没生效，还是没打中物体。如果返回了“No Hit Detected”，请重点消除 (Elimination) 目标物体碰撞通道配置错误的问题。

## 197. 在“鼠标中键”事件节点与“分支（Branch）”节点之间，插入一个 Print String，运行后点击鼠标中键未打印字…

**问题：** 在“鼠标中键”事件节点与“分支（Branch）”节点之间，插入一个 Print String，运行后点击鼠标中键未打印字符

**答案：** 由于在事件起始位置插入 Print String 都没有打印，这证明了输入信号根本没有进入蓝图逻辑。

请按照以下步骤依次排查，以消除 (Elimination) 输入被阻断的情况：

1. 检查蓝图的“接收输入”设置 (Auto Receive Input)

如果你是在一个普通的 Actor 蓝图（而不是 PlayerController 或 Character）中编写逻辑，默认情况下它是不接收键盘和鼠标输入的。

解决方法：

在蓝图编辑器顶部点击 Class Defaults。

在右侧 Details 面板搜索 Input。

找到 Auto Receive Input 选项，将其从 Disabled 改为 Player 0。

消除 (Elimination) 干扰：确保没有其他 Actor 也设置为 Player 0 并勾选了 Consume Input，否则输入会被抢占。

2. 输入模式冲突 (Input Mode)

如果你之前为了操作 UI 或 Cesium 界面设置了输入模式，可能会导致中键被忽略。

排查逻辑：如果你使用了 Set Input Mode UI Only，所有的键盘和鼠标事件都会直接发送给 Widget，而不会触发蓝图中的节点。

解决方法：在加载 UI 时，确保使用 Set Input Mode Game and UI，并勾选 Hide Cursor During Viewport Capture 以外的相关设置，以保证游戏逻辑（蓝图事件）能接收到信号。

3. 增强输入系统 (Enhanced Input) 优先级

如果你使用的是 UE5 模板（如第三人称模板），系统默认启用了增强输入系统。

排查：如果你在蓝图中直接右键搜索并使用了传统的“Middle Mouse Button”节点，它可能会被 Input Mapping Context (IMC) 拦截。

测试方法：

创建一个 Input Action 资产（命名为 IA_MiddleClick）。

将其加入你的 IMC_Default，并绑定到 Middle Mouse Button。

在蓝图中使用 IA_MiddleClick 事件节点替代传统的 Middle Mouse Button 节点。

4. 检查“消费输入” (Consume Input) 属性

虚幻引擎的输入系统有一套优先级。如果另一个蓝图（或 Level Blueprint）也使用了鼠标中键，并且它的优先级更高：

操作：选中你的 Middle Mouse Button 事件节点。

Details 面板：查看 Consume Input。如果它是勾选状态，且有其他同级蓝图也在监听中键，可能导致其中一方失效。尝试取消勾选它，看信号是否能传递过来。

5. 确保视口获得焦点

这是一个物理操作问题：

操作：点击“运行（Play）”后，先用左键在画面中央点击一下。

原因：如果焦点在编辑器面板或 UI 按钮上，鼠标点击事件会被发送到 Slate UI 层，而不会触发游戏场景内的输入事件。

6. 蓝图是否在关卡中？

确认：确保你编写逻辑的这个蓝图已经被拖入到了关卡场景中。如果它只存在于内容浏览器（Content Browser）里，代码是永远不会执行的。

建议总结：
对于你目前的情况，最可能的卡点是第 1 点（Auto Receive Input）。普通 Actor 默认是静默状态，必须手动开启 Player 0 监听，才能消除 (Elimination) 事件不触发的故障。

## 198. 我是在PlayerController中编写的接收输入逻辑

**问题：** 我是在PlayerController中编写的接收输入逻辑

**答案：** 既然逻辑是在 PlayerController 中编写的，那么理论上它拥有极高的输入优先级。如果点击鼠标中键（Middle Mouse Button）连第一个 Print String 都不触发，问题通常集中在 UI 拦截、输入模式配置 或 增强输入冲突 上。

请按以下步骤进行排查，以消除 (Elimination) 信号中断：

1. 检查“Set Input Mode”状态

这是最常见的“静默拦截”原因。如果你在 BeginPlay 或 UI 初始化时调用了 Set Input Mode UI Only，PlayerController 的所有输入事件都会被消除 (Elimination)，信号会止步于 UI 层。

解决方法：确保使用的是 Set Input Mode Game and UI。

注意：即使在 Game and UI 模式下，如果鼠标点击的位置刚好有一个透明的 Widget（控件） 挡住了整个屏幕，且该 Widget 的 Visibility 设置为 Visible（或 Buffered），中键点击会被 UI 消耗掉。

2. 检查 UI 控件的“Handled”回复

如果你使用了 UMG UI 且鼠标在 UI 区域内点击：

排查方法：暂时隐藏所有 UI（调用 Remove from Parent 或设置 Hidden）后再次测试中键。

原因：如果 UI 拦截了鼠标事件并返回了 Handled，PlayerController 将永远接收不到该事件。

3. 增强输入 (Enhanced Input) 的覆盖

在 UE5.1 及之后的版本中，默认项目都启用了增强输入。

冲突点：如果你在 PlayerController 里使用了传统的原生 Middle Mouse Button 事件节点，而项目中存在一个 Input Mapping Context (IMC) 也绑定了鼠标中键，那么增强输入系统会优先拦截该信号，导致原生节点失效。

测试方法：

打开你的 Input Mapping Context (通常是 IMC_Default)。

查看是否有任何 Input Action 绑定了 Middle Mouse Button。

如果有，请直接在 PlayerController 中使用那个特定的 Enhanced Action Event 节点。

4. 消除 (Elimination) 节点的“Consume Input”属性

即使在 PlayerController 内部，节点设置也可能导致问题：

选中你的 Middle Mouse Button 事件节点。

在 Details（细节） 面板中，检查 Consume Input。

操作：尝试取消勾选它。虽然通常 PlayerController 是输入的终点，但在复杂的输入堆栈中，取消勾选可以确保信号不被截断。

5. 验证 PlayerController 是否真正生效

确保你的关卡确实在使用这个特定的 PlayerController：

打开 World Settings（世界设置）。

检查 Selected GameMode > Player Controller Class 是否指向了你编写逻辑的那个类。

测试：在 PlayerController 的 BeginPlay 处接一个 Print String。如果运行后没打印，说明该 Controller 根本没被实例化。

6. 使用调试命令定位

运行游戏后，按下 ~ 键打开控制台，输入：

showdebug input

这会在屏幕上显示当前的输入堆栈（Input Stack）。观察当你按下中键时，列表里是否有对应的响应。这能帮你确认信号是被哪个 Actor 或 Widget 消除 (Elimination) 掉了。

总结排查建议

如果上述步骤都无效，请尝试在 PlayerController 中创建一个最简单的左键点击事件。如果左键能打印而中键不能，说明中键可能在硬件驱动层或系统层被设置为了其他功能（如弹出任务管理器）。如果所有键都不打印，请重点检查 Input Mode 是否被强制锁死在 UI Only。

## 200. 在 PlayerController 中创建一个左键点击事件，运行后原先编写的左键点击功能失效，但屏幕并未打印字符

**问题：** 在 PlayerController 中创建一个左键点击事件，运行后原先编写的左键点击功能失效，但屏幕并未打印字符

**答案：** 这是一个非常关键的信号。原先的功能失效但没有打印字符，说明输入信号确实被拦截了，且拦截点在“执行逻辑”之前。

在 PlayerController 中，这种情况通常由以下三个原因造成，请按顺序消除 (Elimination) 隐患：

1. 终极排查：UI 控件（Widget）的全屏拦截

这是最可能的原因。如果屏幕上存在一个透明的 UI 控件，它的 Visibility 设置为 Visible，它会像一堵无形的墙一样吸收所有的鼠标点击信号。

现象：原有的点击功能（如点击角色移动）被 UI 拦截，信号传不到 PlayerController，所以你的 Print String 也不会执行。

解决方法：

打开你的所有 Widget 蓝图。

检查根节点（Canvas Panel 或 Image）的 Visibility。

将其从 Visible 改为 Self Hit Test Invisible（如果是背景）或 Non-Self Hit Test Invisible。

消除 (Elimination) 测试：暂时断开所有 Create Widget 和 Add to Viewport 的连接，运行游戏测试左键点击。如果此时能打印字符，说明就是 UI 拦截了信号。

2. 增强输入 (Enhanced Input) 的优先级覆盖

如果你在 PlayerController 里手动放了一个原生的 Left Mouse Button 节点，而项目正在使用 IMC_Default：

冲突机制：增强输入系统会优先处理 Input Mapping Context 中的 IA_Action。一旦它识别到左键被绑定到了某个 IA，它就会消除 (Elimination) 掉所有传统的 Left Mouse Button 原始节点。

验证方法：

打开你的 IMC_Default 资产。

寻找绑定了 Left Mouse Button 的 Input Action（通常叫 IA_Click 或 IA_SetDestination）。

在 PlayerController 蓝图中搜索并放置该 IA 节点，在它的 Triggered 或 Started 引脚接 Print String。

3. “消费输入” (Consume Input) 的副作用

如果你的左键功能原本是在 Character 或其他 Actor 中实现的，而你现在又在 PlayerController 中放了一个左键事件：

优先级顺序：输入信号首先经过 PlayerController。

设置检查：选中 PlayerController 中的左键事件节点，查看 Details 面板中的 Consume Input。

如果勾选了：信号会在 PlayerController 处停止，不会传递给后续的逻辑，这解释了为什么“原功能失效”。

但如果还是不打印，说明信号在到达这个节点之前就已经被拦截了（回到第 1 点检查 UI）。

4. 确认 Input Mode（输入模式）

请在 PlayerController 的 BeginPlay 处显式地连接一个 Set Input Mode Game and UI 节点：

将 Widget to Focus 留空。

勾选 Hide Cursor during Viewport Capture 以外的必要选项。

原因：如果系统误进入了 UI Only 模式，所有 Game 层的点击事件（包括 Controller 里的节点）都会被强行消除 (Elimination)。

5. 调试命令：查看谁抢走了点击

运行游戏，按下 ~ 键输入：
showdebug input
在弹出的列表中，观察鼠标点击时，最顶层的响应者是谁。如果最上方显示的是某个 Widget 名字，那么该 Widget 就是阻断信号的元凶。

总结建议：
由于你发现原功能也失效了，90% 的概率是 UI 拦截（Visibility 设置不对）或输入模式被设为了 UI Only。请先尝试断开所有 UI 生成逻辑，回归“纯净场景”进行左键和中键的打印测试。

## 201. MouseSampleRate、Mouse X zero time、Mouse Y zero time 分别代表了什么

**问题：** MouseSampleRate、Mouse X zero time、Mouse Y zero time 分别代表了什么

**答案：** 在虚幻引擎的输入系统底层（尤其是 UPlayerInput 类中），这三个参数主要用于控制鼠标输入的平滑处理（Mouse Smoothing）和原始增量（Delta）的计算逻辑。

当 bEnableMouseSmoothing（启用鼠标平滑）开启时，这些参数决定了引擎如何将不连续的硬件采样转化为平滑的游戏内旋转。

以下是它们的具体含义：

1. MouseSampleRate (鼠标采样率)

含义：这是引擎预期的鼠标采样频率，通常以 Hz（赫兹） 为单位。

默认值：虚幻引擎默认通常设为 0.008333 秒 (约为 120Hz)。

作用：它定义了一个“时间窗口”。引擎会根据这个频率来计算一个标准的时间步长。如果你的鼠标发送数据的速度超过或低于这个频率，引擎会利用这个值来对输入的增量（Delta）进行加权平滑。

影响：调高这个值（缩短时间步长）会使输入响应更灵敏，但如果鼠标本身的硬件回报率不稳，可能会导致视角晃动；调低它则会增加平滑感，但会引入输入延迟。

2. Mouse X zero time / Mouse Y zero time (鼠标 X/Y 归零时间)

这两个参数的逻辑相同，分别对应水平和垂直轴。

含义：它们记录了鼠标在对应轴向上最后一次接收到非零增量的时间戳。

工作机制：

当鼠标移动时，引擎会更新这个时间戳为当前系统时间。

如果鼠标停止移动，由于引擎的“平滑累积”机制，它可能还会残留一部分之前的输入惯性。

当当前时间与这个 zero time 的差值超过了某个阈值（通常由采样率决定）时，引擎会将对应的轴增量强制清零。

作用：它们的主要目的是为了消除 (Elimination) 鼠标停止移动后的“拖尾”感。如果没有这个清零机制，平滑算法可能会让视角在鼠标停下后依然产生极其微小的缓慢漂移。

3. 三者之间的协同逻辑

虚幻引擎处理鼠标输入的简化流程如下：

收集数据：从操作系统获取鼠标的原始 X/Y 偏移。

更新时间戳：如果接收到偏移，更新 Mouse X/Y zero time。

计算平滑：利用 MouseSampleRate 确定的频率，将原始偏移放入一个缓冲区进行加权平均。

检测停止：如果 CurrentTime - zero time 超过预设范围，则执行消除 (Elimination) 逻辑，停止所有的平滑增量输出。

性能与开发建议

禁用平滑：在大多数竞技类或对输入精度要求极高的游戏（如 FPS）中，开发者通常会通过 bEnableMouseSmoothing = false 来关闭这套系统。此时，这些变量将不再影响最终的视角移动，从而实现原始输入 (Raw Input) 的效果。

调试方法：如果你发现鼠标移动有莫名其妙的延迟或“粘滞感”，可以在控制台输入 m.EnableMouseSmoothing 0 来对比测试，确认是否是由于这些采样和归零逻辑导致的干扰。

通过理解这些底层参数，你可以更精准地优化游戏的操控手感，消除 (Elimination) 玩家在高速移动视角时的顿挫感。

如果游戏画面瞬间卡住（暂停）并跳回蓝图：说明逻辑运行了，只是 Print String 出于某种原因没显示（比如时长设为了 0，或颜色设为了透明）。

总结建议

既然 showdebug 已经证明信号到了最顶层，请重点检查 PlayerController 的类关联是否正确 以及 增强输入节点的引脚触发逻辑。如果使用的是 IA 节点，请务必尝试连接 Started 引脚以消除 (Elimination) 触发器设置带来的干扰。

EnableAllScreenMessages

或者 ExecuteConsoleCommand: stats on

4. 消除 (Elimination) 坐标转换为空的逻辑

由于你之前的流程涉及 Cesium 和坐标转换，请确保你的 Print String 节点没有连接一个“空值”。

由于 Tick 不工作且 showdebug 显示响应，最直接的症结就是：GameMode 里的 Player Controller Class 没设对。 请务必检查 World Settings，并利用蓝图编辑器顶部的 Debug Filter 确认你正在观察的正是那个处于 Active 状态的实例。

## 204. 运行后在调试过滤器中，我的蓝图名称是A_PlayerConbtroller，已生成的调试对象是A_PlayerContr…

**问题：** 运行后在调试过滤器中，我的蓝图名称是A_PlayerConbtroller，已生成的调试对象是A_PlayerController0

**答案：** 既然调试过滤器中已经出现了 A_PlayerController0，说明该蓝图确实已经实例化并正在运行。

在这种情况下，Tick 节点不打印、中键节点也不打印，只有一种解释：信号虽然到达了该对象，但输出环节（显示层）被拦截或禁用了。

请按以下步骤操作，以彻底消除 (Elimination) 这种“静默运行”的问题：

1. 强制恢复屏幕打印功能

有时屏幕信息会被控制台变量彻底关闭。

操作：在游戏运行（Play）时，按下键盘上的 ~ 键，输入以下命令并回车：

EnableAllScreenMessages

补充测试：如果依然没反应，输入 stat fps。如果屏幕右上方连帧率都不显示，说明你的视口（Viewport）渲染层屏蔽了所有的调试叠加层。

Print String 是一个 Development Only（仅开发使用） 节点。

检查点：在蓝图编辑器中，选中 Print String 节点。

细节面板：查看其 Development Only 属性。虽然默认是开启的，但请确保你没有在 Shipping（发行） 模式下运行项目，因为该模式会自动消除 (Elimination) 所有 Print String 效果。

操作：在编辑器菜单栏选择 Window（窗口）-> Output Log（输出日志）。

操作：清空日志后，在游戏中点击中键。

排查结果：如果在日志里看到了你打印的内容，说明逻辑在跑，只是屏幕显示层（Canvas/HUD 层）出了问题。

4. 消除 (Elimination) 节点的“显隐”设置

检查 Print String 节点的详细参数（点击节点下方的小箭头展开高级选项）：

Print to Screen：必须勾选（默认为 True）。

Print to Log：必须勾选（默认为 True）。

Duration（时长）：确保不是 0。建议设为 5.0。

Text Color：确保 Alpha 通道不是 0（透明）。

总结建议：
既然实例 A_PlayerController0 已存在，请优先通过 Output Log 确认数据是否已经产生。如果日志里有，屏幕上没有，请尝试使用控制台命令 EnableAllScreenMessages 来恢复被消除 (Elimination) 的屏幕显示功能。

## 206. 手动射线检测具体的蓝图连线逻辑是什么

**问题：** 手动射线检测具体的蓝图连线逻辑是什么

**答案：** 手动射线检测（Manual Line Trace）的核心逻辑是：获取摄像机在鼠标位置的起点和发射方向，并沿该方向延伸出一条足够长的连线。

以下是具体的蓝图连线方案 (Graph Recipe)，请在你的 PlayerController 中按此逻辑连接，以消除 (Elimination) 远距离点击失效的问题：

1. 核心连线步骤

节点 1：Get Player Controller (自身)

作为后续节点的 Target。

节点 2：Convert Mouse Location to World Space

Input: 无需输入，它会自动获取当前鼠标位置。

Output (World Location): 鼠标在世界空间中靠近摄像机近裁剪面的坐标。

Output (World Direction): 从摄像机指向鼠标位置的单位方向矢量（长度为 1）。

节点 3：Vector * Float (乘法)

将 World Direction 连接到输入 A。

将输入 B 设为一个极大值，例如 1000000.0 (代表 10 公里，足以应对 Cesium 的鸟瞰高度)。

节点 4：Vector + Vector (加法)

将 World Location 连接到输入 A。

将 节点 3 的输出 连接到输入 B。

逻辑解释：起点坐标 + (方向 * 距离) = 终点坐标。

节点 5：Line Trace By Channel

Start: 连接 节点 2 的 World Location。

End: 连接 节点 4 的输出结果。

Trace Channel: 保持为 Visibility（或你 Cesium 地形设置的检测通道）。

Draw Debug Type: 设为 For Duration（用于验证红线是否够长）。

2. 获取命中坐标 (Impact Point)

节点 6：Break Hit Result

将 Line Trace By Channel 的 Out Hit 引脚连接至此。

Return Value (Boolean): 连接到一个 Branch (分支)。

Impact Point (Vector): 从这个引脚拉出你的 Print String 或后续的坐标转换逻辑。

3. 资产与属性检查清单

为了确保上述逻辑 100% 成功，请检查以下设置：

Cesium 碰撞体：

选中场景中的 Cesium3DTileset。

在 Details 面板中，确保 Create Physics Meshes 勾选。

将 Collision Complexity 设为 Use Complex Collision as Simple，以消除 (Elimination) 射线穿过低精度地形的问题。

Trace Complex：

在 Line Trace By Channel 节点上，勾选 Trace Complex。这允许射线检测到 Cesium 地形最精细的三角面。

4. 调试与验证

观察红线：运行并鸟瞰，点击地面。如果你看到一条红线垂直射向地面并产生一个绿色的方块（Hit Point），说明检测成功。

打印验证：

如果 Branch 的 True 分支被触发，打印 Impact Point。

如果 Branch 的 False 分支被触发，打印 “No Hit Detected”，这通常意味着你需要进一步调大乘数 B，或者 Cesium 远端瓦片确实没有加载任何碰撞。

性能建议：
虽然设置 10 公里甚至更长的射线不会对性能产生明显影响，但请确保不要在 Tick 中每帧运行这个逻辑。仅在鼠标点击事件触发时运行一次，即可高效地消除 (Elimination) 计算开销。

## 207. GeoReferencingSystem 转换后的 Projected X/Y未打印在屏幕上，在这一步中GeoRefer…

**问题：** GeoReferencingSystem 转换后的 Projected X/Y未打印在屏幕上，在这一步中GeoReferencingSystem的引用变量在程序保存退出后重新打开时总会显示失效

**答案：** 这是由于 PlayerController 是一个频繁销毁与重建的对象（每次切换关卡、停止运行或重启编辑器时都会重置），而你存储的 GeoReferencingSystem 变量属于“实例引用”，这种引用在关卡重新加载后会导致内存地址失效，从而变成 None。

要解决引用丢失并恢复 X/Y 打印，请按照以下方案操作：

1. 消除 (Elimination) 引用失效：改用动态获取

不要依赖手动赋值的变量，而是在逻辑运行瞬间动态查找场景中的系统。

蓝图连线逻辑：

在鼠标点击逻辑的开始处，放置一个 Get Actor of Class 节点。

将 Actor Class 设置为 Geo Referencing System。

从其 Return Value 引脚拉出输出，并右键点击引脚选择 Promote to Variable（提升为变量），命名为 GeoRefSystem_Local。

关键检查：使用一个 Is Valid 节点来判断这个变量。只有在 True 的情况下，才执行后续的 Engine to Projected 转换。

原因：这样可以确保每次运行逻辑时，引擎都会在当前关卡重新定位该 Actor，彻底消除 (Elimination) 因保存重启导致的引用丢失。

2. 检查投影坐标（Projected X/Y）未打印的原因

如果引用已经有效（Is Valid 为 True），但屏幕依然没有 X/Y 的数字，通常是因为数据类型不匹配：

双精度问题 (Double Precision)：GeoReferencingSystem 输出的通常是 Cartesian Coordinates 结构体（包含双精度浮点数）。

连线修正：

从转换节点的输出引脚拉出线，输入 Break CartesianCoordinates。

你会得到三个双精度值（X, Y, Z）。

使用 Append (String) 节点，将 “X: “、”Y: “ 以及对应的数值组合在一起。

最后连接到 Print String。

3. 为什么之前没打印？ (常见故障点排查)

请检查转换节点的输入值：

输入点坐标：确保连接到 Engine to Projected 的 World Location 确实是 Break Hit Result 出来的 Impact Point。

坐标系配置：

选中场景中的 GeoReferencingSystem Actor。

检查 Projected CRS 是否填入了正确的代码（如 EPSG:4539）。

消除 (Elimination) 配置错误：如果 CRS 字符串格式不对或包含非法字符，转换函数会静默失败并返回 (0, 0, 0)。

4. 优化建议：存入 GameInstance 或使用单例

如果你希望在整个项目运行期间都能稳定访问此系统，可以将动态获取逻辑放在 BeginPlay 中，但最稳妥的方式依然是在使用前进行 IsValid 检测。

总结构建顺序：

鼠标点击事件 ->

手动射线检测 (10公里长度) ->

Get Actor of Class (GeoReferencingSystem) ->

Is Valid? ->

(True) Engine To Projected ->

Break CartesianCoordinates ->

Print String。

这种结构能确保即便你重启编辑器一百次，逻辑依然能自动找回引用并正常打印坐标。

## 209. projectedX/Y坐标偏移和鼠标点击时发出的射线检测落点偏移有关吗

**问题：** projectedX/Y坐标偏移和鼠标点击时发出的射线检测落点偏移有关吗

**答案：** 坐标偏移确实与射线检测（Line Trace）的落点偏移有直接关系。在虚幻引擎中，从鼠标点击到获取 ProjectedX/Y 经历了一个完整的“数据依赖链”，任何环节的点位偏差都会被地理转换放大。

以下是误差产生的原因分析以及如何消除 (Elimination) 这些影响：

1. 误差传播链条

你的坐标计算逻辑如下：

鼠标点击：在 2D 屏幕上产生点击位置。

射线检测：从摄像机发出射线，撞击 Cesium 模型的 碰撞体 (Collision)。

获取 Hit Location：返回射线撞击点的 虚幻世界坐标 (Engine World Location)。

地理转换：GeoReferencingSystem 将这个 Engine 坐标转换为投影坐标。

结论：如果射线由于模型碰撞精度问题，“撞”在了距离视觉表面 10 米远的地方，那么最终转换出的 Projected X 就会偏离 10 米。

2. 射线检测产生偏移的常见原因

简化碰撞 (Simplified Collision)：
Cesium 瓦片通常使用粗糙的碰撞网格以节省性能。如果瓦片的 LOD（细节级别）较低，碰撞体可能是一个斜面，即使视觉上你点的是墙角，射线也可能“滑”到了后面或前面的平面上。

复杂碰撞 vs 简单碰撞：
如果你在 GetHitResultUnderCursor 节点中没有勾选 bTraceComplex，射线可能会检测到一个巨大的方块包围盒，而不是具体的楼体模型。这会导致落点产生数十米的偏移。

大世界坐标 (LWC) 精度：
虽然 UE5 使用双精度，但如果你的 Cesium 瓦片距离虚幻原点极其遥远，射线检测可能会出现微小的“抖动”。

3. 如何验证是“点不准”还是“转换不对”？

你需要通过可视化手段消除 (Elimination) 猜疑。在 A_PlayerController 中添加以下调试逻辑：

生成调试球体：在 Line Trace 的 Hit Location 位置调用 Draw Debug Sphere。

视觉对比：

运行游戏并点击。

观察红色调试球是否精确地停留在你点击的那个楼层或地面位置。

如果球偏了：说明是射线检测/碰撞的问题。

如果球位置完美，但 X/Y 还是错的：说明是 GeoReferencingSystem 的 Origin 设置问题。

4. 消除 (Elimination) 偏移的 C++ / 蓝图优化建议

如果你希望提高点击精度，请检查以下设置：

Tileset 设置：在 Cesium3DTileset 细节面板中，确保 Create Physics Meshes 已开启，并将 Screen Space Error 调小，以获取更精细的碰撞模型。

射线参数：确保射线检测使用的是 ECC_Visibility 或自定义的地理检测频道，并务必勾选 Trace Complex。

5. 解决“无访问 (Accessed None)”报错

无论偏移是因为射线没点准，还是原点设错了，只要 X/Y 偏离了 GeoServer 的图层范围，就会导致 features 数组为空。

为了消除 (Elimination) 报错，请在 Array Get 之前强制执行以下逻辑：

使用 Array Length 节点。

如果 Length == 0，直接终止逻辑并打印“点击位置无数据”。

这能确保即便射线点偏了，你的程序也不会崩溃抛红。

核心总结：
如果 1000-2000 米的偏移是稳定且持续的，那通常是 GeoReferencingSystem 的 Origin 设置问题（正如我们之前讨论的投影带对齐）；如果偏移是随机且随视角变化的，那一定与射线检测落点精度有关。
