## 1. ue5.2中可以导入AirSim无人机吗

**问题：** ue5.2中可以导入AirSim无人机吗

**答案：** 在 Unreal Engine 5.2 中使用 AirSim 是可以实现的，但需要注意：微软官方的 AirSim 项目目前已经停止维护并进入归档状态，其官方版本最高仅原生支持到 UE 4.27。

要在 UE 5.2 中运行，你需要使用其社区继承者或特定的分支。以下是详细的解决方案：

1. 推荐方案：使用 Colosseum

Colosseum 是 AirSim 的一个活跃分支（Fork），专门为了支持 Unreal Engine 5（包括 5.2 及以上版本）而开发。它修复了原版 AirSim 在 UE5 中因 API 变更导致的编译错误。

获取方式：在 GitHub 上搜索 CodexLabsLLC/Colosseum。

优势：直接适配 UE 5.2，支持新的增强输入系统，并保持了与原版 AirSim 相同的 API 接口（Python/C++）。

2. 集成到 UE 5.2 项目的步骤

第一步：环境配置

由于 AirSim 类项目涉及复杂的 C++ 编译，必须确保你的开发环境正确：

Visual Studio 2022：必须安装。

组件要求：在 VS Installer 中勾选“使用 C++ 的桌面开发”、“使用 C++ 的游戏开发”以及 MSVC v143 工具链。

注意：UE 5.2 对编译器版本有严格要求，请确保 Windows SDK 版本为 10.0.18362.0 或更高。

第二步：编译插件

下载 Colosseum（或 AirSim 兼容分支）的源码。

运行根目录下的 build.cmd（Windows）或 setup.sh（Linux）。这会编译 AirLib 核心库。

将编译好的 Unreal/Plugins/AirSim 文件夹拷贝到你 UE 5.2 项目的 Plugins 目录下。

第三步：项目设置

转换为 C++ 项目：如果你的项目是纯蓝图项目，请通过“新建 C++ 类”将其转换为 C++ 项目，否则插件无法编译。

启用插件：在编辑器中点击 Edit -> Plugins，搜索并勾选 AirSim。

放置 Actor：在场景中搜索并放置 AirSimSimModeWorldMultiRotor（无人机模式）。

Player Start：放置一个 Player Start，并将其 Tag 设置为 AirSim_Start。

3. 可能遇到的兼容性问题（排除故障）

C++ 标准冲突：UE 5.2 默认使用 C++20。如果编译报错，请在项目的 .Build.cs 文件中确保没有强制设定过时的 C++ 标准。

头文件变更：UE5 移除了许多旧的头文件包含路径。如果你使用原版 AirSim 源码手动升级，需要将大量的 #include "Runtime/..." 修改为更简洁的路径。

性能考量：AirSim 在渲染高分辨率相机图像时非常消耗 VRAM。在 UE 5.2 中建议关闭 Lumen 的实时全景追踪，或在 settings.json 中降低相机的采集频率，以防止显存溢出导致程序被操作系统“淘汰”（elimination）。

4. 替代方案

如果你觉得 AirSim 的配置过于复杂，可以考虑以下更适配 UE5 的现代替代品：

Pegasus (Marketplace)：非常成熟的无人机仿真框架，完美适配 UE5 的物理系统。

Antoinette Project：Epic 官方开源的一套航空仿真工具集，虽然偏向大型飞机，但也涵盖了无人机所需的物理基础。

总结建议： 请前往 GitHub 下载 Colosseum 插件。它是目前在 UE 5.2 中运行无人机仿真最稳定、工作量最小的路径。

## 2. UE5.2可以使用AirSim兼容分支UE5.3的源码的源码吗

**问题：** UE5.2可以使用AirSim兼容分支UE5.3的源码的源码吗

**答案：** 在虚幻引擎开发中，将较高版本的插件源码（如 UE 5.3）“回退”到较低版本（如 UE 5.2）通常是可行的，因为 5.2 到 5.3 之间的底层 API 变化虽然存在，但并不像 4.27 到 5.0 那样具有断代性。

以下是技术可行性分析及操作指南：

1. 技术可行性

API 兼容性：UE 5.3 在渲染渲染管线（RDG）和拓扑结构上做了一些优化，但 AirSim 主要依赖的 Physics（物理） 和 Networking（网络） 模块在 5.2 和 5.3 之间基本保持稳定。

编译挑战：直接运行可能会报错，主要是因为 .uplugin 文件中的版本声明不匹配，以及极少数在 5.3 中新增但在 5.2 中不存在的辅助函数。

2. 操作步骤：如何将 5.3 源码“降级”安装至 5.2

第一步：修改插件描述文件

找到 AirSim 文件夹中的 AirSim.uplugin 文件。

用记事本打开，找到 "EngineVersion": "5.3.0"。

将其修改为 "EngineVersion": "5.2.0"。这是为了消除（eliminate）引擎版本不匹配的警告。

第二步：处理项目环境

确保你的项目是一个 C++ 项目。如果是蓝图项目，请添加一个空白 C++ 类。

关闭编辑器和 Visual Studio。

将 AirSim 插件放入项目根目录的 Plugins 文件夹。

第三步：重新生成与编译

右键点击项目的 .uproject 文件，选择 Generate Visual Studio project files。

打开生成的 .sln 文件，在 Visual Studio 2022 中点击 Build -> Build Solution。

如果报错：

查看输出日志（Output Log）。如果提示某个函数“未定义”，通常是因为 5.3 使用了新的头文件包含方式。

常见修复：检查 AirSim.Build.cs 文件。如果里面引用了 5.3 特有的模块（极少见），需手动将其注释或替换。

3. 可能遇到的风险点

Enhanced Input（增强输入）：UE 5.3 对增强输入系统做了一些小的结构重组。如果 AirSim 的 5.3 分支深度集成了 5.3 版本的输入修饰符（Modifiers），在 5.2 编译时可能会失败。

C++ 标准：UE 5.3 默认使用 C++20。如果你的 5.2 项目配置仍停留在 C++17，需要在项目的 Target.cs 文件中添加 DefaultBuildSettings = BuildSettingsVersion.V4; 和 CppStandard = CppStandardVersion.Cpp20; 以保持对齐。

4. 建议：为什么不直接用 5.2 的兼容分支？

虽然尝试使用 5.3 源码是可行的，但最稳健的做法依然是搜索 Colosseum 或 AirSim 专门针对 UE 5.2 发布的 Release 分支。这些分支已经处理好了 5.2 环境下 MSVC 编译器的特定警告，能让你避开由于编译器严格度不同导致的编译中断。

5. 总结

你可以尝试将 5.3 源码导入 5.2。如果编译通过，其逻辑功能通常是完全正常的。如果编译失败，通常只需修改 .uplugin 中的版本号和修复少量的头文件（Include）错误即可消除（elimination）所有阻碍。

## 3. 我下载了5.2.1版本的Cosys-AirSim，应该如何在UE中启用该插件

**问题：** 我下载了5.2.1版本的Cosys-AirSim，应该如何在UE中启用该插件

**答案：** 要启用 Cosys-AirSim 5.2.1 插件，你需要将其作为一个“项目级插件”安装到你的虚幻引擎 5.2 项目中。由于 AirSim 涉及大量的 C++ 源代码和外部库（如 AirLib），它必须在 C++ 项目中进行编译才能运行。

以下是详细的步骤：

1. 准备 C++ 项目环境

如果你的项目目前是“纯蓝图项目”，插件将无法直接启用，必须先将其转换为 C++ 项目：

在虚幻编辑器中，点击 Tools（工具） -> New C++ Class（新建 C++ 类）。

随意创建一个空白类（如名为 MyDummyClass），点击 Create Class。

引擎会自动生成解决方案文件（.sln）并打开 Visual Studio。

关键： 确保你安装了 Visual Studio 2022，并在安装程序中勾选了 “使用 C++ 的游戏开发” 以及 MSVC v143 构建工具。

2. 放置插件文件

关闭虚幻编辑器和 Visual Studio。

进入你的项目根目录（包含 .uproject 文件的文件夹）。

如果不存在，创建一个名为 Plugins 的文件夹。

将下载并解压后的 Cosys-AirSim 文件夹放入 Plugins 目录下。

正确路径应为：YourProject/Plugins/Cosys-AirSim/Cosys-AirSim.uplugin

3. 编译插件源码

因为 AirSim 包含源代码，你需要通过项目重新编译它：

在项目根目录，右键点击你的 .uproject 文件，选择 Generate Visual Studio project files。

双击打开生成的 .sln 文件。

在 Visual Studio 的“解决方案资源管理器”中，你会看到 Plugins 目录下出现了 Cosys-AirSim。

在顶部菜单选择 Build（生成） -> Build Solution（生成解决方案）。

提示：如果编译报错，通常是因为缺少依赖库。请检查 Cosys-AirSim 目录下是否有一个 build.cmd。如果有，请先右键以管理员身份运行它来预编译相关的核心库。

4. 在编辑器中启用

编译完成后，重新打开 .uproject 文件进入编辑器。

点击菜单栏的 Edit（编辑） -> Plugins（插件）。

搜索 AirSim 或 Cosys-AirSim，勾选 Enabled。

点击右下角的 Restart Now 重启编辑器。

5. 验证与基本设置

放置 World Setting Actor：
在 Content Browser 中搜索插件内容（确保勾选了 Show Plugin Content），找到名为 AirSimSimModeWorldMultiRotor 的 Actor 并拖入场景。

配置文件 (Settings.json)：
AirSim 启动时会读取 Documents/AirSim/settings.json。如果该文件不存在，插件可能无法正常初始化无人机。

示例最简配置：{
 "SeeDocsAt": "https://cosys-lab.github.io/Cosys-AirSim/",
 "SettingsVersion": 1.2,
 "SimMode": "Multirotor"
}

故障排除 (Elimination of Errors)

版本不兼容报错：如果提示版本不是 5.2，打开 Cosys-AirSim.uplugin（用记事本），将 "EngineVersion" 修改为 "5.2.0"。

缺少头文件：确保你的项目 .Build.cs 文件没有强制锁定旧版本的 C++ 标准。UE 5.2 推荐使用 C++20。

无法获取控制权：在 AirSim 运行模式下，通常需要按 F1 查看帮助或按 Backspace 重新获取鼠标控制权。

通过以上步骤，Cosys-AirSim 就会被正式集成到你的环境中，允许你消除（elimination）手动模拟的繁琐，直接进行自动化的无人机仿真。

## 4. The following modules are missing or built with a different …

**问题：** The following modules are missing or built with a different engine version:

 WCWZ_1127
 AirSim

Would you like to rebuild them now?

**答案：** 出现这个提示是因为 WCWZ_1127（你的项目代码） 和 AirSim（插件代码） 的二进制编译文件（Binaries）目前与你运行的虚幻引擎 5.2.1 版本不完全匹配。

请不要点击提示框里的 “Yes”，因为编辑器自带的简易重建功能经常会因为权限或复杂的插件依赖（尤其是 AirSim）而失败。我们需要手动进行“深度清理”和“重新生成”。

请按照以下 5 个标准步骤 彻底解决：

第一步：运行插件的预编译脚本 (至关重要)

Cosys-AirSim 包含一个名为 AirLib 的核心库，它是独立于虚幻引擎编译的。如果这个库没编译，虚幻插件就无法通过编译。

进入项目文件夹：Plugins/Cosys-AirSim。

在该目录下找到 build.cmd。

右键点击 build.cmd，选择“以管理员身份运行”。

等待黑色窗口运行完毕（可能需要几分钟，它会下载并编译 rpclib 等依赖）。

第二步：执行深度清理 (Elimination of Old Files)

清除所有可能导致版本冲突的中间文件：

关闭虚幻编辑器和 Visual Studio。

在项目根目录（.uproject 所在的文件夹），删除以下文件夹：

Binaries

Intermediate

DerivedDataCache

.vs（隐藏文件夹）

WCWZ_1127.sln（旧的解决方案文件）

进入 Plugins/Cosys-AirSim 目录，同样删除里面的：

Binaries

Intermediate

第三步：重新生成解决方案

在项目根目录，右键点击 WCWZ_1127.uproject。

选择 Generate Visual Studio project files。

稍等片刻，你会看到文件夹里重新生成了一个新的 WCWZ_1127.sln。

第四步：在 Visual Studio 中进行强制编译

双击打开新的 WCWZ_1127.sln。

在 Visual Studio 顶部菜单，确认配置为：Development Editor 和 Win64。

在右侧“解决方案资源管理器”中，找到 Games > WCWZ_1127。

右键点击 WCWZ_1127，选择“重新生成 (Rebuild)”。

观察下方的“输出 (Output)”窗口。只要最后显示 Build: 1 succeeded（或更多），就说明问题解决了。

第五步：启动项目

编译成功后，回到项目文件夹，双击 .uproject 文件启动。

这次应该不会再弹出任何报错，直接进入编辑器。

如果编译依然失败，请检查：

Visual Studio 版本：确保你使用的是 Visual Studio 2022（17.6 或更高版本），且安装了 使用 C++ 的游戏开发 工作负荷。

报错信息：如果在第四步失败了，请看输出窗口中最上面的那个 Error。如果报错提到 rpclib 或 AirLib，说明第一步的 build.cmd 没有运行成功（通常是因为网络问题导致无法下载第三方库）。

引擎关联：确保你的 .uproject 文件关联的是 UE 5.2 版本（右键 -> Switch Unreal Engine Version 检查）。

## 5. AirSim.Build.cs该如何修改路径使其能正确找到内部插件

**问题：** AirSim.Build.cs该如何修改路径使其能正确找到内部插件

**答案：** 要使 AirSim 插件能够正确找到内部的 AirLib 依赖项（头文件和库文件），你必须修改插件根目录下的 AirSim.Build.cs 文件。

在 UE 5.2 中，最稳妥的方法是使用 ModuleDirectory（指向当前 .Build.cs 所在的文件夹）来构建相对路径。这样无论你的项目放在哪个盘符，UBT 都能正确找到文件。

AirSim.Build.cs 修改方案

请将 C:\WuCaiWan\Plugins\AirSim\Source\AirSim.Build.cs 文件中的路径解析部分修改为以下逻辑：

using UnrealBuildTool;
using System.IO;

public class AirSim : ModuleRules
{
 public AirSim(ReadOnlyTargetRules Target) : base(Target)
 {
 PCHUsage = PCHUsageMode.UseExplicitOrSharedPCHs;

 // 1. 获取 AirLib 的根目录
 // ModuleDirectory 是 .../Plugins/AirSim/Source/AirSim
 // 我们需要定位到其平级目录 .../Plugins/AirSim/Source/AirLib
 string AirLibPath = Path.GetFullPath(Path.Combine(ModuleDirectory, "..", "AirLib"));

 // 2. 添加头文件包含路径
 PublicIncludePaths.Add(Path.Combine(AirLibPath, "include"));
 PublicIncludePaths.Add(Path.Combine(AirLibPath, "deps", "eigen3"));
 PublicIncludePaths.Add(Path.Combine(AirLibPath, "deps", "rpclib", "include"));
 PublicIncludePaths.Add(Path.Combine(AirLibPath, "deps", "MavLinkCom", "include"));

 // 3. 添加库文件搜索路径（针对 Windows）
 if (Target.Platform == UnrealTargetPlatform.Win64)
 {
 // 确保你已经把从原工程拷贝的 .lib 文件放在了这些目录下
 string LibFolder = Path.Combine(AirLibPath, "lib", "x64", "Release");
 string DepsFolder = Path.Combine(AirLibPath, "deps");

 // 动态合成库文件完整路径
 PublicAdditionalLibraries.Add(Path.Combine(LibFolder, "AirLib.lib"));
 PublicAdditionalLibraries.Add(Path.Combine(DepsFolder, "rpclib", "lib", "x64", "Release", "rpc.lib"));
 PublicAdditionalLibraries.Add(Path.Combine(DepsFolder, "MavLinkCom", "lib", "x64", "Release", "MavLinkCom.lib"));
 
 // 添加系统依赖库，消除链接阶段可能的警告
 PublicSystemLibraries.Add("Shell32.lib");
 PublicSystemLibraries.Add("dinput8.lib");
 PublicSystemLibraries.Add("dxguid.lib");
 }

 // 4. 确保包含必要的引擎模块
 PublicDependencyModuleNames.AddRange(new string[] { "Core", "CoreUObject", "Engine", "InputCore", "RenderCore", "RHI" });
 }
}
关键修复点说明：

消除绝对路径（Elimination of Absolute Paths）：
通过 Path.Combine(ModuleDirectory, "..", "AirLib")，我们实现了路径的自动定位。无论你的插件是在 C:\WuCaiWan 还是其他地方，UBT 都能找到 AirLib 文件夹。

解决头文件找不到的问题 (C1083)：
之前的报错是因为 PublicIncludePaths 使用了错误的相对路径。通过上面的修改，头文件搜索范围将覆盖你拷贝过来的 include 和 deps 文件夹。

修复链接警告 (Link Warnings)：
使用了 PublicSystemLibraries.Add 来处理 Shell32.lib 等系统库，这是 UE 5.2 推荐的写法，可以消除你之前看到的“无法解析为文件”的警告。

最后的物理检查清单：

代码修改后，请务必检查你的文件夹，确保以下文件物理存在：

头文件：C:\WuCaiWan\Plugins\AirSim\Source\AirLib\include\common\Common.hpp

库文件：C:\WuCaiWan\Plugins\AirSim\Source\AirLib\lib\x64\Release\AirLib.lib

操作步骤：

保存 AirSim.Build.cs。

彻底删除 项目根目录的 Intermediate 文件夹。

右键 .uproject 文件 -> Generate Visual Studio project files。

在 VS 中编译。

这样做将彻底解决路径识别问题，使 AirSim 插件能够作为项目的一部分正常编译。

## 6. 这是我的AirSim.Build.cs文件代码，帮我看看怎么修改，哪一行需要修改

**问题：** 这是我的AirSim.Build.cs文件代码，帮我看看怎么修改，哪一行需要修改

**答案：** 针对你在 UE 5.2 环境下迁移 AirSim 出现的“代码 6”以及“Shell32.lib 无法解析”等问题，你需要对 AirSim.Build.cs 进行路径重构和系统库引用优化。

以下是修改后的代码。请注意我标注的 [修改] 部分，你可以直接替换对应的函数或属性。

核心修改后的 AirSim.Build.cs

using UnrealBuildTool;
using System;
using System.IO;

public class AirSim : ModuleRules
{
 private string ModulePath => ModuleDirectory;

 // [修改]：确保路径指向 Plugins/AirSim/Source/AirLib
 // 之前可能指向了 Source/AirSim/AirLib，导致找不到头文件
 private string AirLibPath => Path.GetFullPath(Path.Combine(ModulePath, "..", "AirLib"));

 private string AirSimPluginPath => Path.GetFullPath(Path.Combine(ModulePath, "..", ".."));

 // [修改]：简化路径逻辑，避免在迁移时因为父目录层级改变导致崩溃
 private string ProjectBinariesPath => Path.GetFullPath(Path.Combine(Target.ProjectFile.Directory.FullName, "Binaries"));

 private string AirSimPluginDependencyPath => Path.Combine(AirSimPluginPath, "Dependencies");

 // ... (CompileMode 枚举保持不变)

 private void SetupCompileMode(CompileMode mode, ReadOnlyTargetRules Target)
 {
 // 确保预加载依赖
 LoadAirSimDependency(Target, "MavLinkCom", "MavLinkCom");

 switch (mode)
 {
 case CompileMode.HeaderOnlyNoRpc:
 PublicDefinitions.Add("AIRLIB_HEADER_ONLY=1");
 PublicDefinitions.Add("AIRLIB_NO_RPC=1");
 AddLibDependency("AirLib", Path.Combine(AirLibPath, "lib"), "AirLib", Target, false);
 break;

 case CompileMode.HeaderOnlyWithRpc:
 PublicDefinitions.Add("AIRLIB_HEADER_ONLY=1");
 // 确保加载 AirLib 静态库
 AddLibDependency("AirLib", Path.Combine(AirLibPath, "lib"), "AirLib", Target, false);
 LoadAirSimDependency(Target, "rpclib", "rpc");
 break;

 case CompileMode.CppCompileNoRpc:
 PublicDefinitions.Add("AIRLIB_NO_RPC=1");
 break;

 case CompileMode.CppCompileWithRpc:
 LoadAirSimDependency(Target, "rpclib", "rpc");
 break;

 default:
 throw new System.Exception("CompileMode not recognized");
 }
 }

 public AirSim(ReadOnlyTargetRules Target) : base(Target)
 {
 PCHUsage = PCHUsageMode.UseExplicitOrSharedPCHs;
 bEnableExceptions = true;

 // UE 5.2 必须包含的模块
 PublicDependencyModuleNames.AddRange(new string[] { 
 "Core", "CoreUObject", "Engine", "InputCore", "ImageWrapper", 
 "RenderCore", "RHI", "AssetRegistry", "PhysicsCore", 
 "ChaosVehicles", "Landscape", "CinematicCamera" 
 });

 PrivateDependencyModuleNames.AddRange(new string[] { "UMG", "Slate", "SlateCore" });

 PublicDefinitions.Add("_SCL_SECURE_NO_WARNINGS=1");
 PublicDefinitions.Add("_CRT_SECURE_NO_WARNINGS=1");
 PublicDefinitions.Add("HMD_MODULE_INCLUDED=0");

 // [修改]：显式添加包含路径
 PublicIncludePaths.Add(Path.Combine(AirLibPath, "include"));
 PublicIncludePaths.Add(Path.Combine(AirLibPath, "deps", "eigen3"));

 AddOSLibDependencies(Target);

 }

## 10. 我在UE5.2中启用了Cosys-AirSim插件，告诉我该插件具体的使用方法

**问题：** 我在UE5.2中启用了Cosys-AirSim插件，告诉我该插件具体的使用方法

**答案：** 要在虚幻引擎 5.2 中使用 Cosys-AirSim（AirSim 的高性能分叉版本），你需要完成从环境配置到 API 通讯的一系列步骤。Cosys-AirSim 相比原版 AirSim 优化了对 UE5 特性（如双精度坐标、大世界坐标系统）的支持。

以下是实现无人机加载、操纵以及通过 UI 切换和显示隐藏的具体流程，以消除 (Elimination) 配置过程中的常见障碍。

1. 核心概念

Settings.json: AirSim 的灵魂。它定义了生成什么车辆（无人机/汽车）、初始位置以及 API 的通讯端口。

AirSimHUD: 插件自带的 UI 界面，用于显示基础飞行状态。

API 控制: 即使在编辑器内，AirSim 的车辆通常也是通过外部（Python/C++）或内部蓝图接口进行指令发送的。

2. 环境配置与资产准备

在启动项目前，必须配置 AirSim 的全局配置文件。

路径: 导航至 C:\Users\<YourUser>\Documents\AirSim。

创建/编辑 settings.json:{
 "SettingsVersion": 1.2,
 "SimMode": "Multirotor",
 "Vehicles": {
 "Drone1": {
 "VehicleType": "SimpleFlight",
 "X": 0, "Y": 0, "Z": 0
 },
 "Drone2": {
 "VehicleType": "SimpleFlight",
 "X": 5, "Y": 0, "Z": 0
 }
 }
}

注意：在此处预定义多个车辆，以便后续进行切换和消除 (Elimination) 重复生成的开销。

3. 在场景中部署

添加 PlayerStart: 在你的三维场景中放置一个 PlayerStart。AirSim 会以此为原点（0,0,0）生成 settings.json 中定义的无人机。

设置世界场景设置 (World Settings):

在 GameMode Override 中选择 AirSimGameMode。

这会确保点击“运行”后，插件能够自动接管相机控制并初始化车辆。

4. 实现 UI 控制：模型切换与显隐

由于 AirSim 车辆是动态生成的 Actor（类型通常为 AMultirotorPawn），你需要通过蓝图获取它们的引用。

切换车辆逻辑：

原理: AirSim 默认只允许控制一个“活动”车辆。

实现: 使用 Get All Actors Of Class 获取所有多旋翼 Pawn。

蓝图节点:

通过 API 调用 reset 或使用引擎标准的 Possess 节点让 PlayerController 控制特定的无人机。

调用插件提供的 confirmConnection 确保 API 链路未被消除 (Elimination)。

显隐控制逻辑：

获取引用: 在 UI 按钮点击事件中，使用 Get All Actors with Tag（AirSim 生成时会根据 json 中的名字添加 Tag）。

设置显隐:

调用 Set Actor Hidden in Game 节点。

如果需要彻底关闭物理，还需调用 Set Actor Enable Collision。

5. 操纵方法

手动控制: 运行 PIE 后，直接使用键盘（WASD + 箭头键）即可手动驾驶。

程序化控制 (Python):import cosysairsim as airsim
client = airsim.MultirotorClient()
client.enableApiControl(True, "Drone1")
client.takeoffAsync().join()

6. 性能与最佳实践

消除 (Elimination) 碰撞冲突: 在 UE5 的大场景中，确保无人机初始生成的 PlayerStart 下方没有复杂的碰撞体，防止由于碰撞引起的瞬间爆炸（这是 AirSim 常见的崩溃原因）。

禁用 Tick: 如果场景中无人机数量极多，可以在 settings.json 中调整 ViewMode 为 NoDisplay 来提升性能，或者在 UI 逻辑中将远端无人机的 Toggle Actor Tick 关闭。

7. 常见报错排除

如果提示 “0xc0e90002” 或 DLL 错误：请参考之前的步骤，删除插件目录下的 Binaries 和 Intermediate 文件夹，并使用 Visual Studio 重新生成整个解决方案，以消除 (Elimination) 损坏的二进制文件。

通过以上步骤，你可以在 UE5.2 中建立一个可交互的无人机仿真环境，并利用 UI 系统实现对多个 AirSim Pawn 的精细化管理。
